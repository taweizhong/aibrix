# 07. 实施里程碑与任务排期

## 1. 里程碑总览

## M0：项目脚手架（1 周）

目标：可编译可运行的 Hub/Agent/SDK 空骨架。

任务：

- [ ] 仓库结构初始化（cmd/internal/sdk/api/deploy/docs）
- [ ] 统一配置与日志组件
- [ ] 健康检查与基础中间件
- [ ] CI（lint + unit test）

验收：Hub/Agent 可启动并通过 `/healthz`。

---

## M1：TreeStore + Agent KV MVP（2~3 周）

目标：先打通 KV 基础链路，验证存储与长轮询底座。

任务：

- [ ] TreeStore 内存实现
- [ ] RedisStore + DBStore
- [ ] KV CRUD API
- [ ] KV Watch/WatchPrefix
- [ ] TTL + 过期清理
- [ ] 压测与稳定性测试

验收：KV 秒级 watch、基本降级可用。

---

## M2：Hub 配置管理 + Agent 配置读取（2~3 周）

目标：配置中心最小闭环（不含复杂审批）。

任务：

- [ ] Hub Config CRUD
- [ ] Agent WS 同步（Leader 单连接）
- [ ] Agent Config 拉取 API
- [ ] SDK 初始化拉取与多级合并
- [ ] SDK 文件级解析 API

验收：应用可通过 SDK 拿到合并后的配置。

---

## M3：配置热更新 + SDK 长轮询（2 周）

目标：上线热更新能力。

任务：

- [ ] metadata.hot 筛选
- [ ] SDK 热文件 MD5 上报
- [ ] Agent 端 MD5 比对与长轮询 hold
- [ ] Hub 推送触发 Agent watcher 唤醒
- [ ] SDK onFileChange/onAnyChange

验收：热配置更新后业务回调可在秒级触发。

---

## M4：审批 + 发布状态机（2~3 周）

目标：具备可审计发布流程。

任务：

- [ ] 发布单模型与状态机
- [ ] 飞书审批轮询适配
- [ ] 普通环境发布流
- [ ] 生产多阶段发布流（灰度/生产/稳定/灾备）
- [ ] 回滚流程

验收：发布流程可完整走通并留审计记录。

---

## M5：服务发现 + 完整降级体系（2 周）

目标：补齐第三核心能力与故障体系。

任务：

- [ ] Discovery 注册/发现/心跳
- [ ] Agent 全挂时 SDK 文件缓存兜底
- [ ] Redis/DB 故障注入测试
- [ ] 监控面板与告警规则

验收：故障降级矩阵中的关键路径可演练。

---

## 2. 跨模块公共任务

- [ ] 统一错误码、追踪 ID、审计日志字段
- [ ] OpenTelemetry tracing + metrics
- [ ] 安全基线（内网 + token；后续 mTLS）
- [ ] 文档与示例（QuickStart + FAQ）

## 3. 风险与缓解

1. **Leader 选举方案未定**
   - 缓解：先抽象接口，落地单一默认方案，后续替换
2. **多级合并复杂度高**
   - 缓解：先定义严格合并规则 + golden case 回归
3. **长轮询连接规模大**
   - 缓解：连接池、超时回收、按 app 分桶
4. **审批外部依赖不稳定**
   - 缓解：轮询重试、幂等、人工补偿通道

## 4. 最终验收清单（GA 前）

- [ ] 三大能力都具备生产可用最小特性
- [ ] 关键链路有集成测试和压测数据
- [ ] 提供升级/回滚手册
- [ ] 提供运维手册（巡检、告警、常见故障）
